# Как поддерживать CSS MagazinOT

## Где что изменять

| Задача | Источник |
| --- | --- |
| Общий вид и состояния компонентов | `magazinot_gen.css` |
| Поведение компонентов и создаваемая разметка | `magazinot_gen.js` |
| Примеры компонентов и вариантов | `pages/ui-kit.html` |
| Содержимое страниц | `pages/*.html` |
| Цвета категорий маркировки | `site-assets/data/markirovka/medium-colors.json` |
| Сквозная нормативная навигация | `site-assets/data/markirovka/markirovka-normdocs.json` |
| Построение нормативной навигации | `scripts/generate-markirovka-normdocs.mjs` |
| Общие иконки | `site-assets/icons/ui-icons.svg` |

CSS остаётся одним исходным файлом. Дополнительной сборки стилей нет.
Корень `.mk-ui` задаёт переменные и базовое оформление; классы компонентов
используют префикс `mot-`. Галерея изображений и подсказки могут создавать элементы
вне корня страницы: их стили тоже нужны, даже если этих элементов нет в HTML.

## Как добавлять и изменять компоненты

1. Найдите существующий компонент в UI Kit. Для варианта поведения или плотности
   используйте модификатор того же компонента.
2. Найдите его селекторы в CSS, включая состояния и медиазапросы. Исправьте
   существующее правило. Добавление ещё одной копии в конец файла усложняет каскад.
3. Покажите компонент или новый вариант в UI Kit. Повторяющееся поведение добавляйте
   в общий JS; отдельные `<style>` и `<script>` на страницах запрещены проверками.
4. Выполните подготовку и проверки ниже. При изменении общего CSS проверяются все
   актуальные страницы, а для компонента — мобильный вид, hover, focus и раскрытие.

Цвета маркировки изменяются в JSON. Блок `BEGIN GENERATED MARKER PALETTE` в CSS
строится скриптом. Имена `--medium-…` и `--medium-…-text` используются JavaScript
динамически, поэтому поиск только точной строки в HTML недостаточен для их удаления.

Секции `AUTO:MAGAZINOT_UI_JS` в HTML обновляются из общего JS автоматически.
Не исправляйте их вручную. Карта `scripts/ui-class-map.json` хранит историю миграции,
включая удалённые компоненты, и не считается доказательством использования класса.

## Локальные проверки

Из корня репозитория:

```powershell
node scripts/sync-medium-colors.mjs
node scripts/sync-medium-colors.mjs --check
node scripts/generate-markirovka-normdocs.mjs
node scripts/inject-magazinot-ui.mjs
node scripts/validate-magazinot-ui.mjs
```

С доступными Playwright и Chromium:

```powershell
node scripts/audit-magazinot-css.mjs --check
node scripts/visual-qa.mjs
node scripts/visual-regression-check.mjs
node scripts/test-marker-demo.mjs
```

Аудит CSS использует парсер браузера и ищет классы без ссылок в HTML, JS,
генераторах, JSON, SVG и тестах, а также точные дубли правил в одинаковых условиях.
Он не загружает внешние ресурсы и не изменяет файлы. В CI он выполняется после
установки браузера в двух workflow визуальной проверки.

Это консервативная проверка: ссылка на класс ещё не доказывает его необходимость,
а динамическое построение имени требует отдельного анализа. Аудит дополняется
браузерными проверками. Визуальная проверка использует оригинальные PNG-пиктограммы,
которые workflow берёт из репозитория исходных ресурсов.

## Что удалено при зачистке 2026-10-17

Удалены неиспользуемые классы:

- `mot-select` — на актуальных страницах используется `mot-selectbox`;
- `mot-embed__placeholder`, `mot-figure__placeholder`, `mot-image-placeholder` —
  старые декоративные заглушки;
- `mot-marker-catalog__hazard` — прежний текстовый вариант ячейки;
- `mot-doc-table--first-col`, `mot-table-wrap--sticky-head`;
- `mot-media-fit--left`, `mot-media-fit--top`;
- `mot-media-frame--portrait`, `mot-media-frame--scheme`.

Их можно вводить заново как отдельную задачу с примером в UI Kit. Рабочая разметка
эти классы не использовала. Сохранены все действующие компоненты, состояния и
адаптивные правила. Удалены также ранние объявления, полностью перекрытые поздними
правилами для тех же селекторов и условий, и неиспользуемые переменные.

Оставшиеся `!important` проверяются бюджетом 227. Удаление такой декларации требует
сравнения с CSS самого магазина: совпадение в отдельной HTML-оболочке недостаточно.
Сохраняйте текущий порядок правил до проверки их взаимодействия.
